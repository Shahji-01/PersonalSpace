# Recurring tasks

Task Details → Repeat configures daily, weekly, monthly and yearly schedules, intervals, optional weekly weekdays, monthly last-day rules, and an end date or occurrence count. Migration 0020 adds owner-scoped rules and occurrence metadata. Rules use the shared [rrule library](https://github.com/jkbrzt/rrule); clients submit bounded structured settings rather than arbitrary rule strings.

Fixed schedules advance from the occurrence's original scheduled date, even when completed late or rescheduled for this occurrence only. Months without a selected day (such as the 31st) are skipped; Last day includes every month. After-completion schedules add the interval to the calendar day the user finishes or skips; month/year additions constrain to the final valid day. The mobile command records the action's timestamp and timezone so delayed offline delivery does not use the day of synchronization. Timestamps more than five minutes ahead of the server are rejected.

Completing or skipping an occurrence creates at most one successor in the same transaction. Idempotent retries and reopening/re-completing the original do not create duplicates. A finite schedule ends without a successor. The server allocates successor IDs, so the next task appears after sync; pending completion is labelled in the UI. There is no background job that creates an unlimited backlog of missed tasks.

Edits to title, planned date, deadline, priority, description, estimate, project and tags ask whether to change this occurrence or this and future occurrences. Occurrence-only edits preserve the future template. Future edits create a new rule segment under the same series, retaining earlier occurrences and the remaining count. Change schedule and Stop repeating apply from the current open task. Already advanced tasks direct changes to the next open occurrence. Archive is separate: completing an archived recurring task can still create an active successor; use Stop repeating to end the series.

Successors retain the template's deadline offset from the planned date, deadline clock and timezone intent. Floating times follow the device timezone; fixed times resolve in the stored IANA timezone. For generated fixed deadlines, clock gaps move forward and repeated clock times use the first instant ([Temporal disambiguation](https://tc39.es/proposal-temporal/docs/zoneddatetime.html)). An explicitly chosen instant on the current task is preserved when its date stays unchanged. Date-only after-completion rules can follow the completing device's timezone or keep one timezone. Future edits preserve that choice.

Up to 100 live subtasks are copied from the completed occurrence, reset to todo and assigned to the successor. Their relative dates, descriptions, tags and estimates are retained. Subtask edits therefore carry into the next copy. A subtask cannot have its own repeating rule while its parent repeats; existing independent subtask rules must be stopped before repeating the parent. Parent template scope does not introduce separate subtask templates.

Rules, templates, occurrences, search updates, audit and sync share the existing owner-scoped transaction. Composite foreign keys and forced RLS prevent cross-account links. A rule is erased when its final referencing task is permanently purged; earlier retained occurrences keep their historical rule until purged. Task creation retries retain their original mutation IDs.

Migration 0021 defers recurrence ownership constraints until transaction commit, allowing account-level database cascades to finish before checking successor/rule references. Cross-account and dangling references still fail at commit. The automated fixture verifies this database behavior; a user-facing account-deletion pipeline remains unimplemented.

Automated coverage includes weekdays, leap years, month ends, count/end bounds, generated calendar/timezone invariants, DST folds/gaps, offline completion dates, concurrent retry, scope changes, subtask copying, stop/purge and ownership isolation. Native interaction remains unverified; the emulator was left untouched.
